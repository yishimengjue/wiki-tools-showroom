独立页面 · 蓝白版

五个工具分别怎样把仓库变成 Wiki

每个工具使用一个独立页面。页面中的横向流程会说明：模块负责什么、模块实际调用哪些工具、交给下一步什么结果。

GitHub 仓库快照
→
Wiki 页面、图表与源码引用
01 · 状态机驱动

Local Skill

按固定阶段安排多个 Worker，最终统一校验并发布。

  • Writer：search_code.py + action + 宿主只读工具
  • 控制：runtime.py
  • 输出：.deepwiki/
 02 · 代码索引驱动

deepwiki-open

先索引源码，每个页面再检索相关代码交给模型。

  • Writer：build_page_prompt + RAG.acall
  • 检索：AdalFlow + FAISS
  • 输出：缓存 Wiki / 网页
 03 · 页面队列驱动

OpenWiki

规划页面队列，Worker 逐页读取、写作并提交源码说法。

  • Writer：宿主读写工具 + submit_page
  • 控制：6 个 lifecycle tools
  • 输出：openwiki/
 04 · 代码结构驱动

CodeWiki

先建立组件依赖和模块树，再由 Agent 分层写文档。

  • Writer：read_code_components + editor
  • 分析：tree-sitter + NetworkX
  • 输出：Markdown / HTML
 05 · 在线服务

DevinWiki

提交仓库链接后获得托管 Wiki，内部 Writer 工具未公开。

  • Writer：未公开
  • 用户侧：GitHub + 浏览器
  • 输出：托管 Wiki
