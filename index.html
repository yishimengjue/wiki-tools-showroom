总体结论

五种工具的成品组织方式不同，但篇幅、图表数量和引用数量不能代替事实核查。同一个错误可能出现在多个工具中；另一个工具没有犯错，也可能只是没有写到这一点。要区分“明确写对”“写得不完整”和“根本没说”。

可直接验证：同一个命令，三个工具写错，CodeWiki 指出仓库文档与源码的冲突；同一处理顺序，有工具画错，有工具写对，也有工具没有说明。

成品组织方式

先看实际内容，不按工具名字判断质量

下列为 Ghost 成品的入口，不是整体质量排名。

Local Skill

按模块与子流程拆成多页，文字说明较细。流程图和说明仍需要对照源码检查。

与 DevinWiki 对读
查看顺序错误原文

DevinWiki

按在线教程组织，多页穿插代码、表格和流程图。材料多不等于每条说法正确。

与 Local Skill 对读
查看串行与并行的差异

DeepWiki Open

合成长篇内容，章节中包含相关实现代码。相同主题可以比较文字与代码是否相互支持。

与 Local Skill 对读
查看正确顺序的依据

OpenWiki

按架构、概念和工作流程组织页面，并提供来源入口。具体说法仍须独立核验。

与 Local Skill 对读
查看另一个仓库的顺序错误

CodeWiki

Ghost 以单页总览呈现，包含模块和风险说明。压缩后的过程不一定覆盖全部细节。

与 Local Skill 对读
查看部分说明与完整说明
