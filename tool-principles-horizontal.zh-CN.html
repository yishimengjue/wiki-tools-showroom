结论：Local Skill 的控制和校验最细；deepwiki-open 的核心是“代码索引后再生成”；OpenWiki 的核心是“可恢复页面队列 + 说法绑定源码”；CodeWiki 的核心是“先做语法和依赖分析，再递归写架构文档”；DevinWiki 对使用者最省事，但内部工具链无法审计。工具链更完整不等于内容一定更准确，事实仍需对照源码。

核查来源与边界
  • Local Skill：本地安装的 deepwiki:generate 0.12.0 中 SKILL.md、worker/workflow contract、runtime、inventory、search、validate、publish 脚本。
  • deepwiki-open：官方仓库的 Wiki task、RAG pipeline、repository、content、codemap、API 与前端依赖。
  • OpenWiki：官方仓库的 repository runner、六个 lifecycle tools、Claims、filesystem backend 与 package manifest。
  • CodeWiki：官方仓库的 dependency analyzer、caw toolkit、agent tools、CLI 和 Python manifest。
  • DevinWiki：仅依据 用户侧在线服务和本次取得的托管成品；服务内部实现未公开或本次未测。
