#01P0

Wiki 告诉用户运行 -e google，但程序真正接受的是 -e googles。

会造成什么后果

用户照着文档执行会直接报错，无法启动目标功能，还可能误以为是环境或权限问题。

哪些工具受到影响

本地 Skill、DevinWiki、OpenWiki；仓库 README 和命令帮助本身也写错。CodeWiki 识别出了不一致；deepwiki-open 没有产物。

源码证据说明什么

源码只注册 googles，并会拒绝未注册的 google。这说明仓库原文档先写错，三个 Wiki 又照抄了错误，没有用源码纠正。证据 E1-E3。

应该优先处理什么

立即处理：命令、参数和注册名必须以源码为准；发现 README 与源码冲突时，要在 Wiki 中明确提示。

#02P0

Wiki 说所有连接都会按用户设置的超时时间停止，但第一次 TLS 连接并没有使用这个超时。

会造成什么后果

网络异常时，命令可能比用户设定的时间等得更久，监控或批处理任务可能被拖住。

哪些工具受到影响

本地 Skill、DevinWiki、OpenWiki 写错；deepwiki-open 展示了流程，但没有指出这个限制；CodeWiki 不支持该 Go 仓库。

源码证据说明什么

源码虽然创建了超时控制，但第一次 TLS 连接时没有把它传进去，底层连接器也没有单独设置超时。证据 E4。

应该优先处理什么

立即处理：涉及超时、重试、取消时，必须逐条检查每个分支，不能把一个分支的行为概括成全部行为。

#03P0

同一份 Wiki 对“默认返回格式配置错误”同时给出 406 和 500 两个答案。

会造成什么后果

工程师会写错异常处理和测试用例，排查接口失败时也会判断错原因。

哪些工具受到影响

deepwiki-open。其他已检查工具没有在该具体场景中确认同样错误；未提及不代表已验证正确。

源码证据说明什么

源码和测试表明：没有可用格式且没有默认值时是 406；配置了一个不存在的默认格式时是 500。证据 E5-E6。

应该优先处理什么

立即处理：返回码、异常类型等边界条件应从测试用例提取，并做跨页面一致性检查。

#04P1

Wiki 只说“应该留足内存空间”，却没有告诉读者当前代码实际没有留足。

会造成什么后果

读者会把真实缺陷当成普通注意事项，遗漏可能导致崩溃或内存破坏的风险。

哪些工具受到影响

本地 Skill 弱化了问题；DevinWiki、deepwiki-open、OpenWiki 没指出；CodeWiki 明确发现。

源码证据说明什么

源码允许把数据放到内存尾部附近，随后仍复制完整数据，可能写出边界；还存在分配和释放方式不匹配。证据 E7-E9。

应该优先处理什么

高优先：安全前提一旦被当前实现违反，Wiki 必须直接写成“现有缺陷”，不能只写成建议。

查看证据入口

#05P0

一个 sqlx 示例少接收错误返回值，复制后无法编译。

会造成什么后果

新用户按示例接入会立刻失败，还要额外排查本应由文档避免的问题。

哪些工具受到影响

DevinWiki 的一处示例；同一 Wiki 的其他示例写对，说明页面之间存在不一致。

源码证据说明什么

源码明确规定 Connect 同时返回数据库对象和错误信息，示例必须同时接收 db 和 err。证据 E10。

应该优先处理什么

立即处理：所有代码示例在发布前至少要通过编译或静态检查。

#06P0

CodeWiki 无法处理 Go 仓库，生成任务在开始前就失败。

会造成什么后果

tcping、sqlx 完全拿不到 Wiki；如果批量任务没有预检查，会浪费等待时间并造成覆盖率误判。

哪些工具受到影响

CodeWiki；本轮两个 Go 仓库 tcping 和 sqlx 均失败。

源码证据说明什么

语言检查器列出的支持类型中没有 .go，运行日志也显示模型尚未调用就终止。证据 E11。

应该优先处理什么

立即处理产品口径：生成前展示支持语言并提前拦截；若要覆盖 Go，再补解析和生成能力。

#07P0

Wiki 宣称支持 fileId:nodeId 的短输入格式，但按说明输入通常解析失败。

会造成什么后果

用户会选择一个看起来最简单、实际上不可用的入口，导致调用失败。

哪些工具受到影响

本地 Skill 生成的 Figma Flutter MCP Wiki。URL 输入和分开传参仍可用。

源码证据说明什么

解析器要求整串只出现一个冒号，但合法 nodeId 本身就包含冒号；另一种连字符写法又过不了后续校验。证据 E12-E13。

应该优先处理什么

立即处理：删除不可用写法，或先为每种公开输入格式补通过测试，再允许 Wiki 宣称支持。

#08P1

Wiki 把“不会重复创建页面元素”扩大成“重复初始化完全安全”。

会造成什么后果

开发者可能重复初始化，造成同一个点击被多个监听器处理，出现重复打开或行为异常。

哪些工具受到影响

本地 Skill 生成的 Lightbox2 Wiki。

源码证据说明什么

源码只阻止重复插入页面元素，但每次初始化仍会再次绑定事件；脚本重复加载还会创建新实例。证据 E14。

应该优先处理什么

高优先：描述生命周期时拆开说明“页面元素、事件绑定、实例状态”，不要用一个“安全”概括全部。

#09P1

Wiki 只介绍图片加载成功后的流程，没有说明图片地址失效时会怎样。

会造成什么后果

坏图片链接可能让弹窗一直显示加载中，并暂时失去键盘导航；维护者会漏掉真实用户故障。

哪些工具受到影响

本地 Skill 生成的 Lightbox2 Wiki。

源码证据说明什么

源码只有加载成功处理，没有加载失败处理或超时；仓库路线图也把坏链接列为未解决问题。证据 E15-E16。

应该优先处理什么

高优先：所有加载、网络和文件流程必须同时检查成功、失败和超时三条路径。

#10P0

Wiki 说停止后会输出稳定的最终统计，但程序可能在最后一次探测还没结束时就开始汇总。

会造成什么后果

统计结果可能漏数或不一致；如果一开始就被停止，还可能因为除以零而崩溃。

哪些工具受到影响

本地 Skill、DevinWiki。

源码证据说明什么

源码发出停止信号后没有等待后台探测结束，马上读取仍可能变化的统计值。证据 E17-E18。

应该优先处理什么

立即处理：并发流程必须确认“停止”是否等于“已经结束”，并检查零数据、竞态和收尾顺序。

#13P1

大量页面只有结论，没有任何源码位置可供核查。

会造成什么后果

工程师无法快速判断结论是否可信；这类内容也不适合未经筛选直接作为训练数据。
