五个工具怎样把源码变成 Wiki

五者都接收代码仓库，但“谁安排任务、模型看到哪些代码、在哪里运行”并不相同。图中只写已确认的步骤；DevinWiki 的服务内部实现没有公开，因此不做推测。

流程控制器：决定先做什么、后做什么 模型：阅读材料并写正文 程序处理：建索引、校验、保存 内部不可见

先看最重要的区别

前四个可以在本地控制流程，DevinWiki 是在线黑盒

Local Skill / deepwiki-open / OpenWiki / CodeWiki

代码、配置、模型选择和部分中间产物可检查；工具负责组织流程，模型负责写内容。

DevinWiki

用户提交 GitHub 链接后直接拿到托管页面；本次只能核对输入和成品，无法确认服务内部怎样分工。

01

Local Skill

Python 状态机安排多阶段任务，Codex 或 Claude Code 提供执行宿主和模型。

本地可检查
输入本地 Git 仓库读取文件和目录
→
程序控制建立源码清单筛选核心文件、分组
→
模型参与规划目录与页面模型 / 子 Agent 分工
→
模型参与逐页写作机制、流程、引用
→
程序控制校验并保存输出 .deepwiki
必需依赖Git 与本地仓库Codex 或 Claude Code当前宿主模型Python 状态机Worker / 子 Agent引用与格式校验脚本

本次评测：deepwiki:generate 0.12.0 + Codex + gpt-5.6-sol。不是后来复制出的 basic-wiki-generate。

02

deepwiki-open

先把源码做成可搜索索引，再由模型规划目录并逐页生成。

本地可检查
输入克隆 / 本地仓库读取源码
→
程序处理建立代码索引向量模型 + 本地数据库
→
模型参与确定 Wiki 目录读取文件树与 README
→
模型参与逐页检索并写作失败页可重试
→
程序处理补引用并缓存输出 Wiki 页面
必需依赖Python API文本生成模型向量模型FAISS / 本地索引库Git 仓库网页端使用 Node / Next.js
可选依赖Docker ComposeOpenAI / Gemini / Bedrock / Ollama 等提供方独立 Codemap 两阶段图谱

本次评测：通过 OpenAI-compatible 接口调用配置为 auto 的模型；仓库任务和页面生成均限制为单并发。

03

OpenWiki

文档 Agent 先制定页面计划，再把页面作为队列逐项完成，并记录每条说法的源码依据。

本地可检查
输入Git 仓库读取源码与测试
→
Agent 控制制定文档计划拆分主题和页面
→
队列控制持久化页面任务逐项领取与恢复
→
模型参与逐页生成结论绑定源码证据
→
程序处理校验并落盘输出 openwiki/
必需依赖Node.js 22+OpenWiki CLIDeep Agents JS模型提供方或 Agent 宿主Git 仓库页面队列与证据元数据
可选依赖GitHub Actions 等持续集成MCP / Notion / Slack 等连接器

本次评测：OpenAI-compatible provider + deepseek-v4-flash-0731；连接器不是本次代码 Wiki 的必要输入。

04

CodeWiki

先按目录和模块建立层级，再让多个分析角色处理局部及跨文件关系，最后汇总成架构文档。

本地可检查
输入Git 仓库识别支持的源码文件
→
程序控制模块分层与聚类形成模块树
→
多 Agent分析模块关系局部说明 + 跨文件关系
→
模型参与汇总架构文档职责、流程、风险
→
程序处理校验图并导出Markdown / HTML
必需依赖Python 3.12+CodeWiki CLI多 Agent 分析框架模型提供方Git 仓库Mermaid 校验器
模型接入API provider或通过 caw 调用 Codex / Claude CLI

本次评测：Codex provider + gpt-5.6-sol。两个 Go 仓本轮没有产物，只能说明本次文件识别链路未覆盖，不能扩大为所有版本都不支持 Go。

05

DevinWiki

用户只提交 GitHub 仓库链接，服务端完成处理并返回托管 Wiki；内部生成步骤本次不可见。

在线黑盒
输入GitHub 仓库链接公开或已授权仓库
→
服务内部Devin / DeepWiki 处理模型、拆页、缓存、校验方式未公开或本次未测
→
输出托管 Wiki 网页浏览器直接阅读
用户侧必需GitHub 仓库Devin / DeepWiki 在线服务浏览器与网络私有仓库所需授权

不能确认：服务内部模型、多 Agent、代码索引、重试和事实校验机制。成品风格不能反推出这些实现。

关键理解：模型不是完整工具。模型负责读材料和写文字；Skill、CLI 或在线服务负责选文件、拆任务、重试、校验和保存。相同模型放进不同流程，也会得到不同 Wiki。

说明：Local Skill、deepwiki-open、OpenWiki、CodeWiki 的流程来自本地部署代码、README 和实际评测记录；DevinWiki 只描述用户侧可观察流程。这里说明的是生成机制，不代表任何工具生成的事实一定正确。
