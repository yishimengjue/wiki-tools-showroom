五工具 Wiki 对比
总览工具原理成品对读问题对照

生成机制与实际工具

五种工具，分别查看完整生产流程

选择一个工具进入独立页面。每一步都会说明输入是什么、谁负责处理、使用了什么工具，以及最终生成什么。

输入：同一份 GitHub 仓库快照
↓ 各工具使用自己的读取、调度和模型链路
输出：目录、正文、图表和源码引用组成的 Wiki
01

Local Skill

状态机驱动

固定阶段、Worker 分工、统一重试和最终原子发布。

重点：过程控制最细核心：runtime.py + Codex 子 Agent输出：.deepwiki/
 02

deepwiki-open

代码检索驱动

先建立代码索引，再为每个页面取回相关源码并写作。

重点：大范围相关代码召回核心：AdalFlow + FAISS + RAG输出：缓存 Wiki / 网页
 03

OpenWiki

页面队列驱动

规划器提交页面清单，Worker 逐页完成并登记关键说法的来源。

重点：可恢复页面任务核心：Deep Agents + lifecycle tools输出：openwiki/
 04

CodeWiki

代码结构驱动

先识别函数、类和调用关系，再按模块树从下往上生成架构文档。

重点：模块和跨文件关系核心：tree-sitter + NetworkX + Agent输出：Markdown / HTML
 05

DevinWiki

在线托管服务

提交 GitHub 链接后直接获得在线 Wiki，内部处理工具本次不可见。

重点：用户操作最少核心：服务内部未公开输出：托管 Wiki 网页

怎么比较：先打开任一工具页面理解完整流程，再在页面底部选择另一个工具。可以直接进入 Ghost 同一仓库快照的双栏成品对读。
