Ghost is an evasive shellcode loader designed to hide malicious code execution from both userland and kernel-level detection mechanisms. It employs multiple layers of obfuscation, memory manipulation, and anti-analysis techniques to achieve stealth while executing arbitrary shellcode.

This page provides a high-level overview of the Ghost loader's architecture, components, and operational flow. For detailed information about specific subsystems, refer to their dedicated pages linked in the relevant sections.

Purpose and Capabilities

Ghost enables the execution of arbitrary x64 shellcode while employing multiple techniques to evade detection:

  • AES encryption of shellcode during build
  • Large page memory allocation with randomized placement
  • ETW (Event Tracing for Windows) patching
  • NTDLL unhooking to bypass API monitoring
  • Return address spoofing to evade stack analysis
  • Fiber-based execution to control execution flow

The system consists of two primary components:

  1. A build system that transforms raw shellcode into a stealthy executable
  2. The Ghost loader itself that handles decryption and execution of the shellcode

Sources: Ghost.cpp, build.py

Ghost consists of several interrelated components, each responsible for specific security evasion techniques:

The build system (build.py) prepares the shellcode for execution by:

  1. Encrypting the shellcode with AES
  2. Embedding the encrypted shellcode in a resource file

  4. Generating a C++ executable that contains all necessary functionality

  • Places shellcode at randomized offsets within allocated memory

The memory architecture employs a technique referred to as "large page allocation with random offset" where:

  1. A memory block much larger than needed (2048x the shellcode size) is allocated
  2. The block is filled with random cryptographic data
  3. The actual shellcode is placed at a random offset within this large block
  4. Only the shellcode portion is made executable when needed

This technique makes it difficult for memory scanners to identify the shellcode, as it's hidden within a large block of seemingly random data.

The encryption process consists of these key steps:

  1. Read the raw shellcode binary from the file specified via command line
  2. Generate a random 256-bit (32-byte) key and 128-bit (16-byte) initialization vector
  3. Encrypt the shellcode using AES-256 in CBC mode with padding
  4. Write the encrypted shellcode to icon.ico file
  5. Format the AES key and IV as C-style byte arrays
  6. Update the Ghost.cpp source code with the new key and IV values

5. System Integrity Protection

5.1 ETW Patching

The patch works by:

6. Technical Deep Dive: Memory Concealment

The memory concealment technique deserves special attention due to its effectiveness:

The implementation consists of:

  1. Allocation: The allocate_large_page() function in allocator.h allocates a memory region much larger than needed
  2. Randomization: The memory is filled with cryptographically secure random data

8. Conclusion

The Ghost shellcode loader implements multiple sophisticated security techniques to evade detection. Its layered approach combines build-time encryption, memory concealment, execution obfuscation, and system integrity protection to create a robust evasion platform.

The most notable aspects of its security model are:

  1. The memory concealment technique using oversized allocations and random placement
  2. The fiber-based execution model that hides execution context
  3. The comprehensive use of return address spoofing for almost all function calls

While no evasion technique is perfect, Ghost's multi-layered approach makes detection significantly more challenging for security products.
